# Інтелектуальний AI-помічник

Тема: **Особистий помічник** (система команд `/screenshot`, `/open`, `/search`, `/status` — саме під цю тему з переліку в ТЗ). PyQt6 GUI + Telegram-бот (aiogram) + Gemini API, спільна історія чатів у JSON, логування в реальному часі.

## Швидкий старт

```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# відкрити .env і вписати GEMINI_API_KEY та TELEGRAM_BOT_TOKEN

python main_gui.py
```

- **GEMINI_API_KEY**: https://aistudio.google.com/apikey (безкоштовний ліміт є)
- **TELEGRAM_BOT_TOKEN**: `@BotFather` у Telegram → `/newbot`

Без ключів GUI все одно запускається (можна дивитись інтерфейс), але AI відповідатиме попередженням, а кнопка Start Bot покаже помилку.

## Архітектурні рішення, які варто розуміти (а не просто скопіювати)

**Чому бот у окремому `QThread` зі своїм `asyncio`-циклом.**
PyQt6 має власний event loop (`app.exec()`), aiogram — свій (`asyncio`). Вони несумісні в одному потоці без додаткових бібліотек (`qasync` тощо). Найпростіше робоче рішення для навчального проєкту — окремий потік з `asyncio.new_event_loop()`. Зв'язок назад у GUI — тільки через `pyqtSignal`, бо це єдиний спосіб безпечно чіпати Qt-віджети з чужого потоку.

**Чому `asyncio.to_thread()` навколо виклику Gemini в боті.**
Виклик Gemini API — синхронний і мережевий (кілька секунд). Якщо викликати його напряму всередині `async def handle_text`, він заблокує **весь** event loop бота: поки один користувач чекає відповіді, бот не реагуватиме на повідомлення інших користувачів і на власні команди. Це прямо порушує вимогу п.6 ("виконання команд не блокує"). `asyncio.to_thread` виносить блокуючий виклик у пул потоків, event loop лишається вільним.

**Чому `google-genai`, а не `google-generativeai`.**
Пакет `google-generativeai` (стара документація, `genai.GenerativeModel(...)`) остаточно знятий з підтримки 30.11.2025. Якщо десь у методичках чи старих туторіалах побачите `import google.generativeai as genai` — це вже непрацездатний код. Тут використано актуальний `google-genai` (`from google import genai`, `genai.Client(...)`, `client.chats.create(...)`).

**Чому модель `gemini-2.5-flash`, а не найновіша.**
ТЗ вимагає регулятор температури в GUI. Починаючи з Gemini 3.6 Flash Google прибрав `temperature`/`top_p`/`top_k` з API взагалі — модель сама вирішує "рівень міркування". Тобто на 3.6/3.7 повзунок температури у вашому GUI буде намальований, але нічого не робитиме — і це складно помітити на демонстрації, доки хтось не запитає "а чому відповіді однакові на температурі 0.1 і 2.0". `gemini-2.5-flash` — стабільна модель, яка ще підтримує ці параметри.

## Відомі обмеження (свідомо не докручено)

- **Прив'язка GUI-чату до конкретного Telegram-користувача не реалізована.** У специфікації сказано "Telegram та GUI користуються однією і тією ж історією, якщо це один користувач", але не визначено *як* GUI дізнається, який Telegram user_id — це "той самий користувач". Зараз GUI-чати (`chat_1`, `chat_2`...) і Telegram-чати (`tg_<user_id>`) — окремі простори імен у тому самому `history.json`. Якщо потрібен повний бал за цей пункт: додайте в `.env` змінну `TELEGRAM_OWNER_ID`, і в `main_gui.py` при виборі поточного чату використовуйте `f"tg_{TELEGRAM_OWNER_ID}"` замість `chat_1` — тоді GUI і ваш особистий Telegram-діалог справді розділятимуть один контекст.
- **Бонусні фічі (п.7) не реалізовані** — `/generate_report`, аналітика, `/remind`, погода/новини. Explicitly позначені в ТЗ як необов'язкові; структура коду (окремий файл команд у `telegram_bot.py`) дозволяє додати нову команду за 10 рядків за тим самим патерном, що й існуючі.
- **`/search` обмежений домашньою директорією користувача**, а не всім диском — свідомо, щоб перший же виклик на реальній машині не завис на кілька хвилин і не забив диск.
- **Немає БД** — використано JSON, як прямо показано прикладом у самому ТЗ (розділ 4). БД там позначена "якщо є", тобто опціонально.

## Чого не варто робити далі

- **Не комітити `.env` в git** — `.gitignore` вже це блокує, але перевірте перед `git init`, якщо копіювали файли вручну.
- **Не міняти модель на `gemini-3.6-flash`/`gemini-3.7-flash` без переробки вимоги температури** — див. пояснення вище; або приберіть регулятор температури з GUI, або лишайтесь на 2.5.
- **Не додавайте виклик Gemini напряму в GUI-потік** (без `AIWorker`) — інтерфейс "замерзне" на секунди при кожному повідомленні, це буде видно на демонстрації.
- **Не забувайте `--break-system-packages` при `pip install`**, якщо середовище схоже на це (Linux зі system Python) — інакше `pip` відмовиться ставити пакети глобально.

## Перевірено

Весь код синтаксично валідний і логіка проходить smoke-тести: `ChatHistoryManager` (створення/очищення/контекст чату), `AICore` (конструювання клієнта, конвертація історії у формат SDK), `create_dispatcher` (побудова обробників команд), `MainWindow` (headless-запуск через `QT_QPA_PLATFORM=offscreen`, New Chat перемикає активний чат). Живий виклик Gemini API й реальний Telegram-polling не тестувались — для цього потрібні справжні ключі, яких я не маю.
